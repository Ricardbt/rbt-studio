Cada proyecto nuevo que arrancaba con Claude Code empezaba distinto. Y el resultado era siempre el mismo: specs inconsistentes, y una desconexión entre lo que yo tenía en la cabeza y lo que los agentes acababan construyendo.

Probé skills de planificación ya existentes. Ninguno encajaba: los simples no tenían fondo real, los completos estaban pensados para equipos grandes — mucha ceremonia, cero agilidad.

Así que construí SDD Harness: un wizard Lean de 5 fases (Spec → Architect → Scaffold → Harness Agents → Handoff) con una sola regla no negociable — TDD en cada fase de implementación.

3 meses en uso activo, y ya arrancó proyectos reales (incluida la PRD completa de Job Search OS, pivotando de CRM manual a Career Operating System event-driven). El cambio no se mide en una métrica, se nota en el proceso:

→ Nada se pierde entre la idea y el código funcionando
→ Yo y los agentes hablamos el mismo idioma desde el minuto cero
→ Menos rework, porque los tests son el juez, no la intuición

A veces la mejora no es más estructura. Es la estructura justa, con un ancla que no se negocia.

¿Cómo estructuráis vosotros el arranque de un proyecto con agentes de IA?
